# Decision log

Append-only. Newest at the bottom. Each entry: id, date, decision, reason. Never edit an old entry; if a decision
changes, add a new entry that says it supersedes the old one, and update `design.md`.
Language details live in `design.md`; this file records **that** and **why** a decision was made.

| Id | Date | Decision | Reason |
|---|---|---|---|
| D-001 | 2026-09-08 | Target .NET (now .NET 10) and emit IL directly, not C# source. | Full control, no second compiler in the loop, and it is the learning goal. |
| D-002 | 2026-09-09 | Lexer and parser use ANTLR4, not hand-written. | User's explicit choice after discarding a hand-written lexer. |
| D-003 | 2026-11-01 | Nir is "Kotlin for C#": the CLR object model, C# interop, BCL used directly. Not LLVM. | Interop was the first reason for the language; LLVM would remove the BCL and force a custom runtime and standard library. |
| D-004 | 2026-11-01 | Restart in a new repo (`Nir2`). The old repo is reference only. | Earlier attempts stalled because syntax was built before semantics were settled. |
| D-005 | 2026-11-01 | Build in vertical slices (one feature through all phases), not layer by layer. | A design change then costs one small slice, not a finished layer. |
| D-006 | 2026-11-01 | Bindings are `let` and `let mut`. Parameters are never assignable. | Clear split between "can rebind the name" and "can change the object". Shadow with `let mut x = x`. |
| D-007 | 2026-11-01 | Structs are value types. `&T` is a heap reference, created at the use site (`&T {...}` or `&` of a whole variable), compiled to a generated `Ref<T>`. | Linked structures and sharing need heap references; use-site choice kept (Go-like) over type-site (C# class/struct). Cost accepted: C# sees `Ref<T>`. |
| D-008 | 2026-11-01 | No references into fields or array elements in v1. | The CLR has no heap reference to an interior location. Easy to add later, hard to remove. |
| D-009 | 2026-11-01 | `&self`, `&T` and `&mut T` parameters are borrows (CLR `ref`), cannot be stored. A stored reference must be a heap reference. | Method calls on locals must not allocate. |
| D-010 | 2026-11-01 | Mutability follows the access path (`let mut` for values, `&mut` for heap references). No `mut` on fields. `frozen` types may come later. | Fewer keywords; one rule. Gives up a type-level immutability guarantee for v1. |
| D-011 | 2026-11-01 | No aliasing rules, no borrow checker. `&T` means "no writes through this reference". | Aliasing is inherent to linked structures; a borrow checker is a different language. |
| D-012 | 2026-11-01 | Methods take `&self` or `&mut self` only. No standalone `self`. No ownership or moves. | The GC removes ownership. Standalone `self` would only mean "copy". |
| D-013 | 2026-11-01 | No inheritance. Composition only. | User's choice; keeps the model small. |
| D-014 | 2026-11-01 | Structural (duck-typed) types are deferred, not rejected. | Possible by per-type specialization, but Nir-only and costly; named arguments, defaults and `with` cover v1 needs. |
| D-015 | 2026-11-01 | Modules: `namespace` per file; `using` imports exactly one named thing; no wildcards; `impl` must be in the type's namespace. | Reading a file must show where every name comes from. |
| D-016 | 2026-11-01 | .NET is mirrored under `clr::cs::<Namespace>` (`clr::fsharp` later). Extension methods (Nir and C#) are imported by method name. | Avoid name collisions; keep origin explicit for extensions too. |
| D-017 | 2026-11-01 | `std` is Nir's own library, separate from `clr`. v1 `std` is only a small prelude. | `std::fs` may later wrap the BCL; no need to build it now. |
| D-018 | 2026-11-01 | Errors are values: `E!T`, `try`, `catch`, errors carry data, calls into C# are opt-in `try`, unrecoverable failures crash. | Zig-style handling; C# exceptions become `anyerror` only where the user writes `try`. |
| D-019 | 2026-11-01 | The "nothing" type is `()`. There is no `void` keyword. `anyerror!` means `anyerror!()`. | Tuples already exist; one fewer concept. |
| D-020 | 2026-11-01 | Error types are their own kind: `type E = error {...}`. Returning an error needs the `error` keyword. `T` in `E!T` may not be an error type. | User's choice; makes the failure path visible in code. |
| D-021 | 2026-11-01 | Unions use the keyword form `union { A, B }` for now. `E!T` is shorthand for a union of `E` and `T`. `union` and `match` are in v1. | Multi-error functions need them. `A \| B` may be revisited. |
| D-022 | 2026-11-01 | One `enum` keyword with two shapes: plain values (CLR enum) and cases that carry data. `anytype` dropped. | User wants flexible enums; `anytype` belongs with deferred generics/structural types. |
| D-023 | 2026-11-01 | Emit with `System.Reflection.Emit.PersistedAssemblyBuilder`, writing a `.dll` plus `.runtimeconfig.json`. **Unverified until T1.1.** | Built into .NET 9+, no extra package. |
| D-024 | 2026-11-01 | `nir run` compiles to a temp directory and runs `dotnet <dll>` as a child process. | Isolation and simpler tests than in-process loading. |
| D-025 | 2026-11-01 | One compiler project (`Nir.Compiler`) plus `Nir.Cli` and `Nir.Tests`. | Per-phase projects add ceremony for a one-person compiler. |
| D-026 | 2026-11-01 | ANTLR is temporary and confined to `Parsing/`; everything after it sees only our AST. | User plans to replace it later. |
| D-027 | 2026-11-01 | No blanket `unsafe` around C# calls. Only a narrow marker may be added later for passing immutable values to mutable C# `ref` parameters. | Calling C# must be ordinary, or Nir loses its purpose. |
| D-028 | 2026-11-01 | D-023 verified by the T1.1 spike: `PersistedAssemblyBuilder` output runs with `dotnet x.dll` when a `runtimeconfig.json` is written next to it. | See `architecture.md` section 9. |
| D-029 | 2026-11-01 | Both ANTLR grammars live in one project (`tokenVocab` works there). | Verified in T1.0; no grammar-copy workaround needed. |
| D-030 | 2026-11-01 | Redeclaring a name in the same block is an error. Whether a function body may shadow a parameter is still open. | User's choice; avoids silent name reuse. |
| D-031 | 2026-11-01 | Integer arithmetic is checked: overflow throws. A build flag for wrapping may come later. | User's choice; safer default. Emitted with `add.ovf`, `sub.ovf`, `mul.ovf`. |
| D-032 | 2026-11-01 | Primitive types for now: `int`, `double`, `bool`, `string`. No `float`. | Keep the first numeric slice small. |
| D-033 | 2026-11-01 | No implicit conversions between numeric types. | User's choice; conversion syntax is decided in slice 5. |
| D-034 | 2026-11-01 | Parameters and the function body share one scope, so redeclaring a parameter in the body is an error. A changeable copy needs a new name. This supersedes the "shadow with `let mut x = x`" remark in D-006 and refines D-030. Nested-block shadowing stays open until slice 5. | User's choice; consistent with the same-block rule. |
| D-035 | 2026-11-01 | Slice 2 typing details: operands of an operator must have the same type; `==` and `!=` work on `int`, `double` and `bool` only (not `string` yet); an `int` literal above 2147483647 is an error, so `-2147483648` cannot be written yet. | Keeps slice 2 small; string comparison and a better literal rule arrive with slice 5. |
| D-036 | 2026-11-01 | A failed expression binds to an error-typed node and reports nothing more downstream, so one mistake gives one diagnostic. | Avoids cascades of secondary errors. |
| D-037 | 2026-11-01 | The emitted program's runtimeconfig sets invariant globalization. | Number output must not depend on the machine's locale. |
| D-038 | 2026-11-01 | "Every path returns" uses the simple rule: a function not returning `()` must end with `return value`. Later an `if`/`else` whose branches both end in `return` counts too. No implicit last-expression results. | User's choice; simplest rule, revisited when `match` arrives. |
| D-039 | 2026-11-01 | `return g()` is allowed in a `()` function when `g` returns `()`; returning any other value from a `()` function is an error. | A unit call is not a value, so forwarding it is harmless. |
| D-040 | 2026-11-01 | Parameters are immutable variables (assignment is `NIR3002`). | Follows design.md section 1; consistent with `let`. |
| D-041 | 2026-11-01 | Recursion is checked by the binder in slice 3 but first run in slice 5, because a terminating recursion needs `if`. | Keeps slice 3 honest about what it can test. |
| D-042 | 2026-11-01 | .NET types are found with `System.Reflection.MetadataLoadContext` (package 10.0.0). Every CLR type used when emitting comes from that one context; mixing in runtime types breaks the output. | Spike: lookup and emit work, but a runtime `typeof(void)` in the entry point made the program fail to start. |
| D-043 | 2026-11-01 | `using` lines may appear anywhere at the top level and apply to the whole file; the local name of an import is its last segment. | Simplest grammar; matches design.md section 9. |
| D-044 | 2026-11-01 | Slice 4 supports only methods whose parameter and return types are `int`, `double`, `bool`, `string` or `void`; overloads are chosen by exact argument types. | Keeps the first interop slice small; wider type mapping comes later. |
| D-045 | 2026-11-01 | `NirCompiler.Compile` and `Emit` hold one process-wide lock around the shared `MetadataLoadContext`. | The context is not assumed thread safe; compilation is quick, so serializing it costs nothing. |
| D-046 | 2026-11-01 | `Environment`-style properties, constructors, generics and other .NET members are not callable yet; only methods over `int`, `double`, `bool`, `string` and `void`. | Slice 4 scope; wider mapping needs arrays, objects and generics (slice 11). |
| D-047 | 2026-11-01 | Diagnostics are printed in rustc's style: header, ` --> file:line:col`, the source line with a gutter, carets under the span with the message beside them, and a final error count; coloured on a terminal, plain when redirected (`NO_COLOR`, `CLICOLOR_FORCE`). | User's request; much easier to read than one line per error. |
| D-048 | 2026-11-01 | Only the first lexical or syntax error of a file is reported (the one nearest the start). | ANTLR's recovery makes follow-on errors that are mostly wrong; Python does the same. Revisit with a better parser. |
| D-049 | 2026-11-01 | Conditions must be `bool` (no truthy values). Braces are always required, parentheses are not. `if` is a statement. `else` may start on the next line. | User accepted the control-flow design. |
| D-050 | 2026-11-01 | Loops are `while cond { }` and `for i in a..b { }` (end excluded; `a..=b` includes it). `a`, `b` are `int`, evaluated once; `i` is a fresh immutable `int` each pass. `break` and `continue` apply to the innermost loop; no labels and no `loop { }`. | User accepted the control-flow design. |
| D-051 | 2026-11-01 | Boolean operators are `&&`, `||` and `!`, short-circuiting, on `bool` only, with the precedence in design.md "Control flow". | C-style, familiar to C# users. |
| D-052 | 2026-11-01 | A nested block may not declare a name that an enclosing block, a parameter or a `for` variable already declares; sibling blocks may reuse names. Refines D-030 and D-034 and closes the open question about nested blocks. | C#'s rule; consistent with the parameter decision. |
| D-053 | 2026-11-01 | "Every path returns" also accepts a final `if` / `else` whose branches both return. Loops never count. Extends D-038. | As planned in D-038. |
| D-054 | 2026-11-01 | Strings and conversions (`+`, `==` on strings, `$"..."`, escapes, `as`) move out of slice 5 into a new slice 6; later slices are numbered one higher. `x as double` and `d as int` are the planned conversions, and `d as int` throws when out of range. | Smaller slices; slice 5 is control flow only. |
| D-055 | 2026-11-01 | String escapes in plain and interpolated strings are `\n \t \r \\ \" \{`; anything else after a backslash is an error. Interpolated strings also have `{{` and `}}`. | User accepted the recommendation. |
| D-056 | 2026-11-01 | `as` converts between `int` and `double` only. `d as int` truncates toward zero and throws when out of range or NaN. `as` binds tighter than `*` and looser than unary `-`. | User accepted the recommendation; consistent with checked arithmetic. |
| D-057 | 2026-11-01 | `{x}` in `$"..."` prints the value's `ToString()` with invariant culture, and may hold any expression that has a value. String `+` takes two strings; `==` / `!=` on strings are ordinal. | User accepted the recommendation. |
| D-058 | 2026-11-01 | Struct fields and struct literal fields are separated by a comma or a newline. Struct literals are `Point { x = 1, y = 2 }`: every field once, any order, `=`, no defaults. | User accepted. |
| D-059 | 2026-11-01 | A struct literal cannot appear directly in the head of an `if`, `while` or `for` (Rust's rule); parentheses, call arguments and interpolation holes lift the restriction. | Without it `while n != limit { n = n + 1 }` is ambiguous. User accepted. |
| D-060 | 2026-11-01 | Borrow parameters are in slice 7, and the borrow is written at the call: `bump(&mut p)`, `show(&p)`. `&x` / `&mut x` can only be an argument for a borrow parameter for now, only of whole variables, and only for structs. | User chose the explicit call-site form over deferring them. Keeps `&` meaning "reference to this variable" for slice 10. |
| D-061 | 2026-11-01 | `==` on structs, `print(struct)` and a struct in an interpolation hole are errors for now. `with` is deferred. | User accepted. |
| D-062 | 2026-11-01 | Slice 8 is split: 8a tuples, 8b unions and `match`. Slices 9 and later keep their numbers. | User chose smaller commits. |
| D-063 | 2026-11-01 | Tuples: anonymous `(int, double)` types in signatures and `let`, literals `(1, 2.5)`, access `t.0`, destructuring `let (a, b) = t`; named tuples through `type Pair = (x: int, y: int)` with access `p.x`. Compile to `ValueTuple`. | User accepted both forms. |
| D-064 | 2026-11-01 | `match` uses the draft form `value: Type => expr` per arm, works as a statement and as an expression, arms may be blocks, all arms of an expression have one type, and a non-exhaustive match is an error. | User accepted. |
| D-065 | 2026-11-01 | A union can hold any existing Nir type (primitives, structs, tuples), emitted as a tagged struct so primitives are not boxed. | User accepted. |
| D-066 | 2026-11-01 | Tuple details for 8a: two or more elements, no upper limit (past seven they nest through `ValueTuple.Rest`, as C# does); same type means same element types (names are not part of the type, so `Pair` and `(int, int)` convert freely); names are all-or-none; `let (a, mut b, _) = t` with per-name `mut` and `_` discard; a tuple element is an assignable place like a struct field; `==`, `print` and interpolation of tuples are errors; no borrows of tuples; `t.0.1` is read as two indexes (the lexer sees a decimal number). | Smallest rules that make tuples useful; mirror the struct decisions D-061. |
