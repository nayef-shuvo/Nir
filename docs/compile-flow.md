# How a file is compiled, step by step

This follows one real program from `nir run demo.nir` to its output. Every dump below (tokens, tree, bound tree, IL) is the real output
of the compiler for this file, not an illustration.

```rust
fn square(n: int) -> int {
    return n * n
}

fn main() {
    let x = 7
    if x > 3 {
        print($"square is {square(x)}")
    }
}
```

Read `docs/code-map.md` for what every file does; this document is about the **order of events**.

## 0. The big picture

```g4
nir run demo.nir
  Nir.Cli/Program.Main          parse the command line
  Nir.Cli/Commands.Run
    TryCompile                  read the file, build a SourceText
      NirCompiler.Compile       (Nir.Compiler/NirCompiler.cs, takes the global lock)
        SyntaxParser.Parse        text -> tokens -> parse tree -> AST      (stops here if there is a syntax error)
        Binder.Bind               AST -> bound tree + diagnostics           (names, types, rules)
      DiagnosticPrinter.Print   show every diagnostic, Rust style
    NirCompiler.Emit            bound tree -> IL -> demo.dll + demo.runtimeconfig.json   (Emitter.Emit)
    start `dotnet demo.dll`     the .NET runtime runs it; its exit code becomes ours
```

Three data structures carry the program from phase to phase, and each phase is the only one that knows the one before it:

| Phase | Output | Defined in |
|---|---|---|
| Parsing | the **AST**: immutable records, no meaning attached | `Syntax/` |
| Binding | the **bound tree**: the same program, but every name is a symbol and every expression has a type | `Semantics/BoundNodes.cs` |
| Emit | **IL** in an assembly | `Emit/` |

Problems never throw. Every phase reports a `Diagnostic` (code `NIR####`, message, span) into one `DiagnosticBag`. An exception means a compiler bug
(`Program.Main` turns it into "internal compiler error", exit code 3).

## 1. The command line and the file

`Program.Main` calls `CommandLineArguments.TryParse` (`build <file> [-o dir]` or `run <file> [-- args]`). `Commands.TryCompile`:

1. checks the file exists and that its name (without `.nir`) is only letters, digits, `_`, `-` (it becomes the assembly name: `demo`);
2. reads the text and wraps it in `new SourceText(path, text)`. `SourceText` can turn a position into line and column and fetch a line's text; every
   diagnostic keeps a reference to it so the printer can show the source line later;
3. calls `NirCompiler.Compile`, prints all diagnostics to stderr, and returns exit code 0, or 1 if any error.

Exit codes: 0 ok, 1 compile error, 2 usage error, 3 internal error (`ExitCodes.cs`).

## 2. Lexing: text to tokens

`NirCompiler.Compile` first takes `lock (ClrUniverse.Gate)` (the .NET type reader used later is not thread-safe, so one compilation at a time) and creates the
`DiagnosticBag`. Then `SyntaxParser.Parse` creates the lexer: `new NirLexer(new AntlrInputStream(text))`.

`NirLexer` is generated by ANTLR from `Parsing/NirLexer.g4` (at build time, by the `Antlr4BuildTasks` package). It derives from our `NirLexerBase`
(`superClass` option), whose `NextToken()` post-processes what the generated lexer produces. For the demo the result is:

```g4
1:1   FN           fn                    keywords come before IDENTIFIER in the grammar, so `fn` is FN, not a name
1:4   IDENTIFIER   square
1:10  LPAREN       (
1:11  IDENTIFIER   n
1:12  COLON        :
1:14  IDENTIFIER   int                   `int` is a plain name here; the binder decides it is a type
1:17  RPAREN       )
1:19  ARROW        ->
1:22  IDENTIFIER   int
1:26  LBRACE       {
2:5   RETURN       return
2:12  IDENTIFIER   n
2:14  STAR         *
2:16  IDENTIFIER   n
2:17  SEMI         \n                    <- a newline became a statement terminator (see below)
3:1   RBRACE       }
3:2   SEMI         \n\n                  <- blank lines are one token, and also a SEMI
5:1   FN           fn
...
8:9   IDENTIFIER   print
8:14  LPAREN       (
8:15  INTERP_STRING_START $"             <- a string mode starts
8:17  INTERP_TEXT  square is
8:27  HOLE_START   {                     <- `{` inside the string: back to normal tokens
8:28  IDENTIFIER   square
8:34  LPAREN       (
8:35  IDENTIFIER   x
8:36  RPAREN       )
8:37  HOLE_END     }                     <- the `}` that closes the hole (a RBRACE retyped by NirLexerBase)
8:38  INTERP_STRING_END "
8:39  RPAREN       )
8:40  SEMI         \n
```

What `NirLexerBase` adds to the generated lexer:

- **Newline to `;`.** Semicolons are optional. The grammar only recognises `NEWLINE` and `;`; `NextToken` rewrites a `NEWLINE` into a `SEMI` when two things hold:
  the bracket depth is 0 (inside `( ... )` a newline is just whitespace, so multi-line calls need no trailing comma) and the previous token can end a statement
  (`EndsStatement`: a name, number, `true`, `false`, `return`, `break`, `self`, `!`, a string end, `)` or `}`). Otherwise the newline is dropped, so
  `x +` newline `y` continues. Line 6 `let x = 7` ends with an INT_LITERAL, hence the `SEMI` at `6:14`.
- **Strings.** `"` switches the lexer to the `PLAIN_STRING` mode, `$"` to `INTERP_STRING` (see the `mode` sections of the grammar). In an interpolated string a `{` pushes the
  default mode (ordinary tokens) so the hole holds a normal expression; `NirLexerBase` counts braces to know which `}` closes the hole and retypes it `HOLE_END`
  (a struct literal or nested string inside a hole therefore works). An unterminated string is reported once (`NIR0002`) and repaired so the parser still sees a closed string.
- **Errors.** An unknown character is `NIR0001`.

## 3. Parsing: tokens to a parse tree to the AST

`new NirParser(new CommonTokenStream(lexer))` is the parser generated from `Parsing/NirParser.g4`. `parser.compilationUnit()` is the start rule:

```g4
compilationUnit : terminator? (topLevelItem (terminator topLevelItem)*)? terminator? EOF
topLevelItem    : usingDirective | functionDeclaration | structDeclaration | tupleAliasDeclaration | unionDeclaration | implDeclaration
```

Key points of the grammar:

- The `expression` rule is **left recursive** and its alternatives are listed from highest to lowest precedence (ANTLR's convention): member call and field access,
  unary, `try` / `error`, `&`, `as`, `* / %`, `+ -`, comparisons, `== !=`, `&&`, `||`, `catch`, then the primaries (calls, parentheses and tuples, literals, `match`, struct and error
  literals, names). Order also resolves ambiguity: `error Name { }` is an error literal because that alternative comes first.
- `Name {` is ambiguous in `if x {`: is `x { ... }` a struct literal? The parser has a counter `_structLiteralsForbidden` (C# code in the grammar's `@members`) that is raised while an
  `if` / `while` / `for` head is parsed (and lowered inside parentheses, call arguments and interpolation holes); the struct-literal alternative has a **semantic predicate** `{_structLiteralsForbidden == 0}?`.
- Errors: `ParserErrorListener` receives every ANTLR syntax error, rewrites ANTLR's token names into plain words (`a name`, `the end of a statement`) and reports `NIR1001`. `SyntaxParser.Parse` collects lexical and
  syntax problems and keeps **only the first by position** (after one syntax error the parser's recovery guesses, and later errors would mostly be noise).

The ANTLR parse tree is then converted by `AstBuilder` (`Parsing/AstBuilder.cs`, the only code that reads ANTLR classes) into our own immutable records (`Syntax/`). For the demo:

```g4
CompilationUnit
  FunctionDeclaration square(n: int) -> int
    Block
      Return
        Binary *
          Name n
          Name n
  FunctionDeclaration main
    Block
      VariableDeclaration let x
        IntLiteral 7
      If
        Binary >
          Name x
          IntLiteral 3
        Block
          ExpressionStatement
            CallExpression print
              Interpolated
                Text "square is "
                Hole
                  CallExpression square
                    Name x
```

`AstBuilder` also decodes string escapes (`StringEscapes`, unknown escapes are `NIR0003`), splits things the lexer glued (`t.0.1` is lexed as `t`, `.`, the number `0.1`), and tolerates the half-built tree ANTLR leaves after a
syntax error (it returns `null` for missing parts instead of throwing).

Back in `NirCompiler.Compile`: **if the diagnostics now contain an error, compilation stops** and the binder never runs.

## 4. Binding: the AST gets meaning

`Binder.Bind(unit, source, diagnostics)` creates a `ProgramBinder` (one big partial class, split by topic) and calls `Bind(unit)`. It runs in **passes**, so order in the file never matters:

| Pass | What | Where |
|---|---|---|
| imports | `using clr::cs::System::Math` becomes names in `_imports` | `.Imports.cs` |
| 0 | declare struct / error / union names, tuple aliases; resolve union members and struct fields; check no struct contains itself | `.Structs.cs`, `.Unions.cs`, `.Tuples.cs` |
| 1 | declare every **function signature** (name, parameter and return types) into `_functions`, so a call may come before the definition | `ProgramBinder.cs` `DeclareFunction` |
| 1c | the methods of every `impl` block | `.Methods.cs` |
| 2 | **bind every body**: `BindFunction` for each function and method | `ProgramBinder.cs` |

`main` must exist (`NIR2002`). Then the result is `new BoundProgram(structs, unions, functions, entryPoint)`, or `null` if any error was reported (`_hadError`).

### How one function is bound

`BindFunction(function)` starts a fresh `ScopeStack`, declares the parameters in the first scope (the body shares it, so a local cannot reuse a parameter's name), then `BindStatements(body)`. Every statement goes through
`BindStatement` (a switch over the AST node type); every expression through `BindExpression`. They return **bound nodes**, each with a `Type`.

For `square`: `return n * n` -> `BindReturn` -> `BindExpression(Binary *)` -> `BindBinary`: bind both sides (`BindName` looks `n` up in the scopes and yields a `BoundVariableExpression`), then
`BinaryResultType(Multiply, int, int)` checks the operand types are the same and numeric and returns `int`. The return type must equal the function's declared type (via `Convert`, which also does the union conversions). After the
body, `BoundFlow.AlwaysReturns` checks every path returns (`NIR3007` otherwise).

For `main`:

- `let x = 7`: `BindVariableDeclaration` binds the **initializer first**, then declares `x` (so `let x = x` cannot see itself). The type is the initializer's: `int`. `BindIntLiteral` checks the literal fits in 32 bits.
- `if x > 3 {...}`: `BindCondition` requires `bool`. `BindBlock` pushes a new scope for the block and pops it after (a name declared inside is gone afterwards).
- `print($"...")`: `BindCall` first looks for a user function named `print`; there is none, so it asks `BuiltinFunctions` (overloads of `Console.WriteLine` for `int`, `double`, `bool`, `string`) and picks the one whose parameter type is exactly the
  argument's type (`string`).
- The interpolated string: `BindInterpolated` makes every part a `string`. The text stays a literal; the hole `{square(x)}` is a call of a user function (`BindUserCall` -> `CheckUserCallArguments`: arity and types) of type `int`, and a non-string
  part is wrapped in a call of its own `ToString()` (`ToStringPart`, found by reflection over the .NET `Int32` type).

The result for `main` (real dump, shortened):

```g4
BoundVariableDeclaration   Variable: x: int      Initializer: BoundIntLiteral 7
BoundIfStatement
  Condition: BoundBinaryExpression Greater (x, 3) : bool
  Then: BoundBlock
    BoundExpressionStatement
      BoundCallExpression  Target: print
        BoundInterpolatedString
          BoundStringLiteral "square is "
          BoundMemberCallExpression Target: ToString
            Receiver: BoundCallExpression Target: square (x)
```

### Types, symbols, and "one mistake, one error"

- A **type** is a `TypeSymbol` (`int`, `double`, `bool`, `string`, `()` are static singletons; structs, tuples, unions, results, `anyerror` are subclasses). `==` on types is overloaded (tuples and results compare structurally).
- A **symbol** is a resolved name: `VariableSymbol`, `UserFunctionSymbol`, `ClrMethodSymbol` (a .NET method), `StructTypeSymbol`...
- When an expression is wrong, the binder reports **one** diagnostic and returns a `BoundErrorExpression` whose type is `TypeSymbol.ErrorType`. Every check treats `ErrorType` as "already reported, say nothing more". That is why
  `let x: int = "hello"` followed by `print(y)` gives exactly two errors (one per mistake), and `1 + missing` gives one:

```
error[NIR3001]: cannot convert 'string' to 'int'          line 2:  let x: int = "hello"
error[NIR2001]: 'y' is not defined                         line 3:  print(y)
error: aborting due to 2 previous errors                   (exit code 1; nothing is emitted)
```

## 5. Emit: the bound tree becomes a .dll

`NirCompiler.Emit` refuses a result with errors, takes the lock again and calls `Emitter.Emit(program, "demo", directory)`. It uses `System.Reflection.Emit` in its **persisted** form (`PersistedAssemblyBuilder`, .NET 9+), which builds an
assembly in memory and can write it to disk without running it.

### The CLR types come from `ClrUniverse`

The compiler never loads the BCL to run it; `Clr/ClrUniverse.cs` creates a `MetadataLoadContext` over the runtime's assemblies and reads types from there (`Int32`, `String`, `Console`...). `TypeSymbol.IntType.ClrType` is that
`Int32`. Everything that goes into the emitted assembly must come from this universe, never from `typeof(...)`, or the types don't match. `Clr/ClrTypes.cs` caches the few used all the time, and `ClrMethods` finds methods by
name and parameter types (cached per type).

### The order of work in `Emitter.Emit`

1. `PersistedAssemblyBuilder(name "demo", core assembly from ClrUniverse)` and a module.
2. Define the class `Program` (every free function is a static method of it).
3. Define the generated types **before any member**: `Nir.AnyError` (the base of errors), struct classes/value types, union types; then their fields (a field may be of a type declared later).
4. **Declare every method** (`DefineMethod` with its CLR parameter and return types from `EmitContext.ClrOf`), for all functions. Bodies come after, so a body can call any method.
5. For each function, `new BodyEmitter(il, context, function).EmitBlock(body)` writes the IL. A `()` function ends with `ret`; one returning an `E!` that falls off the end gets an implicit success.
6. Create the types (`CreateType`; `Nir.AnyError` first), `GenerateMetadata`, and serialize with `ManagedPEBuilder`, whose **entry point** is the method for `main` (or, for `main -> E!`, a generated `Main` that prints `error: ...` and exits 1).
7. Write `demo.dll`, and `demo.runtimeconfig.json` (`RuntimeConfigWriter`): the target framework and `System.Globalization.Invariant: true`, so output does not depend on the machine's locale.

### What `BodyEmitter` produced (real IL, with the explanation)

```g4
method Int32 square(Int32 n)
  ldarg 0          n               <- parameters are read straight from their argument slot
  ldarg 0          n
  mul.ovf                          <- checked multiplication: overflow throws OverflowException (design decision)
  ret

method Void main()
  ldc.i4.7                         <- let x = 7 ...
  stloc.0                          <- ... x lives in local 0
  ldloc.0   ldc.i4.3   cgt         <- x > 3  (pushes 0 or 1)
  brfalse IL_0028                  <- skip the block when false (the label at the end)
  ldstr "square is "               <- the first part of the interpolated string
  ldloc.0   call Program::square   <- square(x)
  stloc.1                          <- an int is a value type: store it in a temporary local ...
  ldloca.s 1                       <- ... take its address ...
  call Int32::ToString             <- ... and call ToString on it (that is what BodyEmitter.Calls.cs does for value-type receivers)
  call String::Concat              <- joins the two parts
  call Console::WriteLine          <- print
  ret                              <- IL_0028: both paths end here
```

The files written: `demo.dll` (about 2.5 KB) and `demo.runtimeconfig.json`:
`{"runtimeOptions":{"tfm":"net10.0","framework":{"name":"Microsoft.NETCore.App","version":"10.0.0"},"configProperties":{"System.Globalization.Invariant":true}}}`.

## 6. Running

`nir build` stops after writing the two files into `-o dir` (default `./out`) and you run `dotnet out/demo.dll` yourself. `nir run` emits into a temporary directory, starts `dotnet <dir>/demo.dll <args>`, waits, deletes the
directory and returns the program's exit code. The `dotnet` host reads `demo.runtimeconfig.json`, loads the framework, finds the entry point, the JIT compiles the IL to machine code and it runs:

```
square is 49
```

An unhandled exception (overflow, a failing .NET call without `try`) ends the process with a non-zero code and a stack trace on stderr (`samples/crashes/`).

## 7. How the other features use the same flow

Every later feature added a branch to each phase and nothing else: a grammar rule and an AST record (`Syntax/`), a binder method plus a diagnostic code (`Semantics/ProgramBinder.*.cs`), a bound node (`BoundNodes.cs`) and
one `case` in `BodyEmitter.EmitExpression` or `EmitStatement`.

| Feature | Parsing | Binding | Emit |
|---|---|---|---|
| structs, methods | `structDeclaration`, `implDeclaration` | `.Structs.cs`, `.Methods.cs`, `.Borrows.cs` | value types with fields; instance methods get the address of the struct; `&mut` is a CLR `ref` |
| tuples | `tupleType`, `tupleLiteral` | `.Tuples.cs` | `System.ValueTuple` (nested `Rest` past 7) |
| unions, `match` | `unionDeclaration`, `matchExpr` | `.Unions.cs` (`Convert`, `BindMatch`) | a value type with `Tag` and one field per member; `match` tests the tag |
| errors, `try`, `catch` | `error`, `try`, `catch`, `E!T` | `.Errors.cs` (a result type is a union of `E` and `T`) | classes deriving `Nir.AnyError`; `try` returns early; a .NET call under `try` runs in a generated `Protected<n>` helper with a CLR try block |

## 8. Things worth noticing (small improvements left on the table)

- `ldarg 0` is emitted in its 4-byte form; `ldarg.0` / `ldarg.s` would shrink the IL (`BodyEmitter.Expressions.cs`, `EmitExpression` for `BoundVariableExpression`). Harmless, since the JIT does not care.
- The printed token/tree/bound-tree/IL dumps above were produced by a throwaway test; the roadmap backlog lists `nir dump tokens|ast|bound|il <file>` commands, which would make this kind of exploration a one-liner.
- Each phase ends at the first phase that reports an error (`NirCompiler.Compile` returns after parsing if there is a syntax error), so a program with a syntax error never gets type errors reported, by design.

2. `NirLexer.g4` and `NirLexerBase.cs`: tokens and the newline rule.
